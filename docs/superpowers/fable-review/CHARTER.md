# Fable 전면 검토 헌장 (2026-11-11 시작, 약 6일)

kista-api·kista-ui·kista-infra 세 레포 공통 기준이다. 각 레포의 Fable 오케스트레이션 세션이 이 문서를 따른다.

## 목적

구현이 아니라 **분석과 지침서**가 산출물이다. Fable 한도가 끝난 뒤 Opus/Sonnet이 지침서만 보고 무리 없이 실행할 수 있어야 한다.

- 현실적 타협보다 이상적 설계를 지향한다. 지금 비용이 커도 된다.
- 코드 철학(재사용성·가독성·최신 문법, 비일관성 > 중복 > 보일러플레이트 > OOP 위반 > 과설계) 중심의 과감한 리팩토링 방향을 낸다.
- "기능에 비해 코드가 비대하다"가 핵심 문제의식이다. 인라인 수준 지적(api-audit류)은 가치가 낮다. 개념·구조 수준에서 "이 코드가 왜 존재해야 하는가"를 묻는다.

## 사용자 확정 사항

1. 기존 "유지 확정·재론 금지" 목록(memory, code-quality-backlog 유지 목록 등)은 **전체 항목 1회 재심 허용**. 재심 결과 유지면 이유를 지침서에 남긴다.
2. 모든 전제가 재검토 대상이다: 2-프로세스 분리, DB 5스키마, Spring Modulith, 헥사고날 포트 구조, 매매 공식까지. 매매 공식은 https://quantstack.app 을 기준 문헌으로 삼는다(KISTA 무한매수법은 4.0). 정리본은 `kista-api/docs/reference/quantstack/`.
3. 테스트 코드 감량도 목표에 포함하되 별도 주제로 다룬다(동작 보존 근거가 줄어드는 위험 때문).
4. 산출물 위치는 각 레포의 `docs/superpowers/fable-review/`.
5. 문서 정리도 범위다: CLAUDE.md·docs·README·memory를 과감히 걷어내고 필요하면 구조를 개편한다(자동 로드 토큰 비용 포함).
6. 불필요한 파일 삭제도 범위다: 참조 없는 소스·스크립트·설정·잔재를 근거와 함께 목록화한다. 삭제·대량 개편의 실행은 사용자 승인 후.
7. 서브에이전트는 한도로 죽을 수 있으니 항목 단위로 findings 파일에 바로 기록하게 하고, 죽으면 새로 띄우지 말고 SendMessage로 재개한다.

## 역할 분담

- Fable(오케스트레이터): 주제 선정, 핵심 파일 직접 읽고 목표 설계 판단, 지침서 작성. 탐색·측정·기계적 정리는 하지 않는다.
- 서브에이전트(Sonnet/Haiku, `model` 명시): 측정·탐색·요약. 결과는 대화가 아니라 `fable-review/findings/<주제>.md` 파일로 쓰고, 반환은 15줄 이내 요약만. 프롬프트에 "git add/commit 금지" 명시.

## 단계

1. **측정**: 코드를 읽기 전에 숫자부터. 기능 1개당 파일·줄 수(수직 추적), 같은 개념의 타입 복제 횟수, 평행 구조(종류별로 같은 모양 반복), 구현 1개뿐인 추상화·호출처 1곳뿐인 간접층, 테스트 비대 원인, 기존 유지 확정 목록 요약.
2. **판단**: 측정에서 상위 5~8개 주제 선정. 주제마다 핵심 파일만 직접 읽고 이상적 목표 구조 결정.
3. **지침서**: 주제당 1파일 `fable-review/guides/NN-<주제>.md`. 아래 형식.
4. **레포 간 계약**: api 응답·`/api/meta`·에러 코드·배포 구조처럼 레포를 넘는 변경은 `kista-api/docs/superpowers/fable-review/cross-repo.md` 한 곳에 모은다.

## 지침서 형식

- 현재 구조와 문제 (file:line 근거, 줄 수)
- 목표 구조, 그렇게 정한 이유, 기각한 대안
- 예상 감량(파일·줄)과 위험
- 동작 보존용 선행 테스트
- 태스크 분해: 태스크별 대상 파일, 권장 모델(Opus/Sonnet/Haiku), 완료 판정 명령
- 하지 말아야 할 것, 다른 지침서와의 의존·순서

## 중단 대비 (5시간 한도)

- `fable-review/PROGRESS.md`를 단계가 끝날 때마다 갱신하고 커밋한다: 완료 항목, 산출물 경로, 바로 다음 할 일.
- 주제 하나를 측정부터 지침서까지 끝낸 뒤 다음 주제로 간다.
- 새 세션은 CHARTER.md → PROGRESS.md → findings/ 순으로 읽고 이어간다.
