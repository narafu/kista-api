## com.kista.sharedkernel (`:shared`)

com.kista.sharedkernel/ ← 순수 어휘 패키지. `@ApplicationModule(Type.OPEN)` — outbound reference 0인 값 타입만 담아 다른 모듈을 참조하지 않는다는 전제(`HexagonalArchitectureTest.sharedkernel_must_not_depend_on_other_modules`). user/account 모듈은 소비만 하고 소유하지 않는다. 승격 경위 → history "sharedkernel 승격 경위"
  공유 enum       ← UserRole/UserStatus/NotificationType/NotificationChannel(NONE/TELEGRAM/FCM/ALL — user 설정 저장 + notify 채널 라우팅 공유, 2026-09-30 user.domain.model에서 재승격)/StrategyType/StrategyStatus/StrategyTicker/StrategyCycleSeedType/Broker(TOSS/KIS/MOCK)/OrderDirection/OrderType/OrderStatus/OrderTiming/MarketSession(DIRECT/BLOCKED — market·marketcalendar·`DstInfo` 3중 복제 통합, 2026-09-30)/BenchmarkGranularity(MONTHLY/DAILY/WEEKLY — root stats·trading-core stats 복제 통합, 2026-09-30). KIS/Toss wire 매핑은 어댑터 코드가 담당(enum 값 집합엔 외부 계약 없음). 
  정책·기본값     ← RecurringMode/StrategyCreationSettings/StrategyFieldSettings(전략 생성 정책 — 자체 검증 로직을 가진 record도 outbound-zero면 포함)/StrategyDefaults(`DEFAULT_DIVISION_COUNT=20` — PRIVACY/VR처럼 분할 수 설정이 없는 전략의 고정값)
  전략 capability ← `StrategyCapability(availableTickers, tickerFixed, requiresPrivacyBase, supportsReverseMode, divisionCounts)` + `StrategyType.capability()` — 전략별 정적 상수의 SSOT(INFINITE: 전체 티커·리버스모드·분할 20/30/40 / PRIVACY: SOXL 고정·기준표 필요 / VR: TQQQ 고정). `StrategyType.availableTickers()`는 이에 위임하고, matching `CycleOrderStrategy`의 capability 기본 메서드와 root `MetaController`가 같은 상수를 프로세스 간 HTTP 없이 공유한다(2026-09-30, 구 `/api/internal/matching/strategy-capabilities/{type}` 삭제). `availableTickers`는 EnumSet 순서를 유지(UI 티커 정렬)
  유틸            ← `TimeZones`(KST 단일 소스)/`AccountNumberMasker`(계좌번호 마스킹 SSOT). `UsTradeDates`는 어댑터 전용이라 sharedkernel이 아닌 `platform.time` 소속
  값 타입         ← `ReturnMetrics`(자산곡선 성과 지표 순수 계산 — root `HousingBenchmarkComparisonBuilder`·trading-core `BacktestEngine`/`BacktestService` 공용)/`TradeLegSummary`(direction/ticker/quantity/price/amountUsd 5필드 — `broker.Execution`의 notify 전용 narrowing). 전부 sharedkernel enum+JDK 타입만 참조. `TradingReport`/`DailyCandle`은 trading-core 전용이라 각각 `trading.domain.model`/`tradingstats.domain.model` 소유
  이벤트          ← `UserDeletedEvent`(발행 주체는 user, 구독은 trading·finance·account 등)/`UserNotifyProfileChangedEvent(userId, notificationPrefs, balanceCheckEnabled, active)`/`UserPushNotificationRequestedEvent`(trading-core→root FCM 전용, Redis Stream `stream:user.push-notification.requested`로 크로스프로세스 전달)/`UserNotificationRequestedEvent(userId, type, title, body)`(root 내부 — 발행 모듈이 notify를 모른 채 사용자 알림을 요청하는 통합 이벤트, `type`은 `UserSettings.notificationPrefs` 게이트 키. 현재 finance 리마인더가 발행하고 notify `UserNotificationRequestedListener`가 채널 라우팅). 매매·privacy 알림 이벤트 12종은 소비자가 trading-core 안뿐이라 각각 `trading.application.event`/`privacy.application.event`로 환원됐다(root는 0건 사용). 이벤트 FQCN을 옮기면 `event_publication`에 `ClassNotFoundException`이 남는다 → constraints.md Flyway 절
  정책 묶음       ← `TradingPolicySettings(brokers, strategies)`/`BrokerSettings` — trading-core가 소유·집행하고 root admin이 내부 API(PUT /api/internal/trading/policy-settings) body로 편집하는 매매 런타임 정책. 프로세스 간 계약이라 sharedkernel에 둔다
