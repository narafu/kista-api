## com.kista.web (`:api`)

com.kista.web/       ← Spring Modulith 앱셸 모듈. `@ApplicationModule(Type.CLOSED)` — NamedInterface **0개**. 아무 모듈도 web을 참조하지 않는 sink라 순환에 참여할 수 없다(`HexagonalArchitectureTest.web_must_stay_pure_inbound_sink`가 trading-core 대칭 셸 `tradingweb`과 함께 `web → ..application.service../..adapter.out..` 의존 금지로 강제). **신규 파일이 단일 모듈만 소비하거나 모듈 의존이 없으면 web에 두지 말고 소유 모듈로 보낼 것** — 여기엔 진짜 다중 모듈 fan-out과 순환 회피용 포트 구현체만
  GlobalExceptionHandler ← root 소유 컨트롤러(admin/user/finance/benchmark/market/web) 전용 예외→HTTP 매핑(`@RestControllerAdvice`). 범용 JDK/Spring 예외 9종은 `platform.web.ProblemDetailMappings.GENERIC`이 공급하고 이 클래스는 root 고유 엔트리(`InvalidRefreshTokenException`·admin own-type 3종·`TradingPolicyUnavailableException`·finance 6종 등)만 `withGeneric(...)`으로 얹는다. trading-core 예외 6종은 `tradingweb.TradingExceptionHandler`가 전담. 500 catch-all은 admin `AppErrorLogPort`를 직접 호출하지 않고 `AppErrorRaisedEvent`(sharedkernel)를 발행한다(발행 실패는 삼키고 warn) — 저장은 admin `adapter/in/event/AppErrorRaisedListener`가 담당하므로 web → admin 포트 의존은 없다(admin 도메인 예외 import만 남음)
  RootSecurityPolicy    ← `platform.security.SecurityRoutePolicy` 구현 `@Component` — root 프로세스 고유 라우트 규칙 9개(`/telegram/webhook`·`POST /api/client-errors`·`/api/auth/**`·`GET /api/market/**`·`GET /api/meta`·`GET /api/runtime-config` permitAll, `/api/auth/status-stream`·`/api/trades/stream`·`DELETE /api/auth/me` authenticated)를 기존과 같은 상대 순서로 기여(구체 경로가 `/api/auth/**` permitAll보다 먼저). `SecurityConfig`가 공통 규칙 뒤에 적용하므로 이 정책이 admin/internal 경로를 permitAll로 열 수 없다. trading-core 셸(`tradingweb`)은 기여할 규칙이 없다
  MetaController        ← `GET /api/meta` — enum 메타(label/description) 단일 번들. finance(`domain.model`)+sharedkernel(`StrategyType.capability()` 상수 포함) fan-out이라 단일 모듈 이관 불가, UI enum 리터럴 하드코딩 방지. 내부 API·RestClient 호출 없음(trading-core 장애와 무관하게 응답, 응답 shape 불변) — `HexagonalArchitectureTest.inbound_adapters_must_not_perform_outbound_http`가 `adapter.in..`·`web..`의 `org.springframework.web.client..` 의존을 금지한다
  AdminSchedulerController ← benchmark "schedule" 소비 — KbLand 스케쥴러 수동 트리거(`/api/admin/scheduler/kbland-*`). 클래스 레벨 `@ConditionalOnProperty(scheduler.enabled)`라 kista-api role에선 빈 미등록(오라우팅 시 404)
  dto/                 ← MetaBundle·EnumMeta·StrategyTypeMeta(`from(StrategyType)` — `StrategyType.capability()`에서 조립)·TickerMeta
