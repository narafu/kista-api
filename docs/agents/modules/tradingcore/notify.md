## com.kista.tradingcore.notify (`:trading-core`)

com.kista.tradingcore.notify/ ← Spring Modulith 모듈(CLOSED) — 매매 알림 6종과 그 게이트웨이. **순수 리스너·게이트웨이 sink(NamedInterface 없음, 외부 소비자 0)** — trading이 발행하는 이벤트 15종(DCA 회차 미주문 `DcaRoundSkippedEvent` 포함 — `TradingAlertNotifier`가 구독해 사용자 알림)(`trading.application.event`, `"event"` NamedInterface)·privacy `PrivacyAlertRaisedEvent`를 구독하고 `trading.domain.model`("domain")/`trading.application.port.output`("port")를 읽을 뿐이라 trading은 이 모듈을 모른다(`trading → tradingcore.notify` 참조 0). 루트 notify 모듈이 아니라 trading-core 소속이며 모듈 ID는 `trading-notify`(api.notify의 `notify`와 겹치지 않게 — 한 애플리케이션 Modulith 모델). `ApiApplication`의 `scanBasePackages`(`com.kista.tradingcore`)에 포함된다(`TelegramProperties`는 `com.kista.shared.platform.telegram` 소유라 `PlatformAutoConfiguration`의 `@EnableConfigurationProperties`가 바인딩)
  application/port/output/ ← TradingNotifyPort/TradingRealtimeNotificationPort/TradingUserNotificationPort — `User` 대신 trading-core 소유 경량 프로필 타입(`trading.domain.model.TradingUserProfile`)을 받는 알림 출력 포트. 소비자는 모두 이 모듈 안이다(trading은 알림을 직접 호출하지 않고 이벤트만 발행)
  adapter/out/gateway/ ← TradingNotifyAdapter/TradingUserNotificationAdapter/RedisPushNotificationPublisher(`PushNotificationStreamConsumer`가 받는 `stream:user.push-notification.requested`로 XADD — 내구성 push. XADD 실패는 삼키고 error 로그 — 알림 리스너가 트랜잭션 밖 발행 지점에서 인라인 실행돼 예외가 사이클 재등록 등 매매 흐름을 끊기 때문, Redis 장애 순간 푸시는 유실. 본문은 텔레그램 HTML을 평문으로 바꿔 위임 `toPlainText`)/RedisTradeEventPublisher/TradingUserProfiles + 매매 알림 리스너 6종(TradingAlertNotifier/CycleEndedNotifier/CycleLifecycleNotifier/OrderCancelFailureNotifier/TradingReportNotifier/PrivacyAlertNotifier). Telegram HTTP(`TelegramHttpClient`/`TelegramConfig`/`TelegramProperties`)는 root notify와 공용인 `com.kista.shared.platform.telegram`을 주입받는다(빈 이름 `telegramRestClient`/`telegramHttpClient`). 실시간 알림 wire는 `contract.notify.TradeEventMessage`/`TradeEventEnvelope`(root 구독측과 공유)

**사용자 봇 발송 규칙**: 매매 알림은 trading-core `tradingcore.notify`가 `trading.user_notify_profile` 복제본 기준으로 발송하며, 토큰·chatId·텔레그램 채널 중 하나라도 없으면 조용히 건너뛴다.

**EPR 소유**: 한 컨텍스트의 `public.event_publication` 하나를 `kista-worker`만 재발행한다(`REPUBLISH_OUTSTANDING_EVENTS_ON_RESTART=true`, docker-compose.yml. `kista-web`은 false — 둘 다 true면 이중 claim). 매매 알림 리스너는 worker에서 자기 미완료 이벤트를 재기동 시 재발행한다. `trading.event_publication`은 3 role 시절 레거시다.

`ApiKeyExpiryNotifier`는 account `ApiKeyExpiringEvent`(`ApiKeyExpiryScheduler` 10:00 KST, D-30/D-7/D-0)를 구독해 `notifyApiKeyExpiring`을 호출하며, 키가 만료되면 매매가 멈추므로 TRADING_ALERT 설정과 무관하게 보낸다. 트랜잭션 밖 발행이라 `fallbackExecution = true`.
