### BrokerCapabilitiesPort + BrokerRouter 패턴
- 공통 6개 Port(Portfolio/Margin/SellableQuantity/BrokerOrderCorrection/Execution/BrokerPrice) + `BrokerAdapterPort`를 묶은 `BrokerCapabilitiesPort`를 KIS/Toss/Meritz/Mock 어댑터가 구현한다 — 통계 2개 Port(Candle/ExchangeRate, `BrokerStatisticsPort`로 묶음)는 `TossBrokerAdapter`만 추가 구현하며 벤더 중립 값 타입만 반환한다 — 소비자(tradingcore.stats `BrokerStatisticsService`)는 `BrokerStatisticsPorts.find(Broker.TOSS)`로 조회하고 없으면 `IllegalStateException`
- `com.kista.tradingcore.broker.application.service.BrokerRouter`(package-private, `@Primary @Component`): `List<BrokerCapabilitiesPort>`를 `Map<Broker, BrokerCapabilitiesPort>`로 수집해 공통 6개 Port를 **개별로** 구현하고 `account.broker()`로 위임한다. `BrokerCapabilitiesPort`/`BrokerAdapterPort`를 구현하지 않는 이유 — 구현하면 자기 자신이 `List<BrokerCapabilitiesPort>`에 수집된다. 미등록 브로커는 `IllegalArgumentException("지원하지 않는 증권사: ...")` → 공용 advice 400
- 소비처(trading 등)는 `BrokerPricePort` 같은 Port 인터페이스를 그대로 주입 — `@Primary`가 Router를 고른다(어댑터 3개도 같은 타입 빈이라 Router가 없으면 모호)
- 신규 브로커 추가: `BrokerCapabilitiesPort` 구현체 1개만 추가 — Router/switch 수정 불필요
- 브로커 분기 필요 시 `account.broker() == Broker.TOSS` 직접 비교
- "application" NamedInterface는 `BrokerConnectionTesters`/`BrokerCallGuard` 공개용으로 유지
- `BrokerCallGuard` 실패 정책 짝: `wrap`=fail-closed(실패 시 중단·예외 전파, 증권사 타입 예외는 상태코드 보존), `tryGet`=fail-open(실패 시 경고 로그 후 `Optional.empty()`로 건너뜀). 이벤트 발행·분기 처리가 필요한 실패 처리만 직접 catch
