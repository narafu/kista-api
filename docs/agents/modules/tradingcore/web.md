## com.kista.tradingcore.web (`:trading-core`)

com.kista.tradingcore.web/ ← Spring Modulith 앱셸 모듈. root `com.kista.api.web`과 대칭. `@ApplicationModule(Type.CLOSED)` — NamedInterface **0개**. 아무 모듈도 tradingcore.web을 참조하지 않는 sink라 순환에 참여할 수 없다(`HexagonalArchitectureTest.web_must_stay_pure_inbound_sink`가 `com.kista.api.web..`과 함께 `application.service`/`adapter.out` 의존 금지로 강제). trading-core 프로세스 전체(부팅·전역 web)에 걸치는 관심사만 두고, 특정 모듈 소유 코드는 소유 모듈로 보낼 것
  (없음) TradingApplication ← 이 모듈이 아니라 `com.kista.tradingcore` 루트에 있다(`@SpringBootApplication @ConfigurationPropertiesScan @EnableScheduling @Modulithic(additionalPackages = "com.kista.shared")`). 스캔 목록이 없고 루트 기본 스캔이 trading-core 전체를 덮는다. `bootJar` 매니페스트 `Start-Class`는 `com.kista.tradingcore.TradingApplication`(Dockerfile은 `java -jar trading-core.jar`라 변경 불필요). 테스트는 `@SpringBootConfiguration` 상향 탐색으로 이 클래스를 찾으며 `@ContextConfiguration`을 쓰지 않는다. `JpaRepositoryConfig`는 없다 — 루트 기본 스캔이 리포지토리 15개를 덮어 별도 `@EnableJpaRepositories` 클래스가 필요 없었다
  (삭제됨) JpaRepositoryConfig ← 폴백 없이 제거. 별도 SchedulingConfig 분리도 없다
  TradingExceptionHandler ← 프로세스 전역 `@RestControllerAdvice`(`basePackages` 없음, `@Order(HIGHEST_PRECEDENCE)`). 전용 핸들러는 `BrokerApiException` 503·검증 실패뿐이고, trading-core 고유 예외(`BrokerCredentialException` 422/`BrokerRateLimitException` 429/`ManualTradingException`·`OrderCancelException`·`PrivacyTradeConflictException`·`Account.DuplicateAccountException` 409 등)는 `MAPPINGS = withGeneric(...)` 테이블 한 곳에서 catch-all(`catchAll`)이 처리한다. `BrokerApiException` 503(title은 벤더 표기 도출, detail은 사용자 노출용 고정 문구 — 원본 메시지는 로그·에러 로그에만, `AppErrorRaisedEvent` 발행 → `AppErrorStreamPublisher`가 `stream:app.error`로 root에 전달) + 범용 JDK/Spring 예외(`GENERIC`은 MAPPINGS에 병합, `isClientDisconnect` 가드) + 미매핑 500. root와 같은 JVM에 공존하지 않으므로 root `GlobalExceptionHandler`와 별개로 존재하되 매핑 테이블·탐색·검증 메시지는 `ProblemDetailMappings`를 공용한다
  TradingSecurityPolicy ← `platform.security.SecurityRoutePolicy` 구현 `@Component`(root `RootSecurityPolicy`와 대칭) — trading-core 고유 공개 라우트 1개(`GET /api/crypto-market-indicators` permitAll — 계좌·사용자 무관 공개 시세라 비회원 대시보드에 노출)를 기여한다. 같은 매처를 `anonymousFallbackMatchers()`로도 내놓아 무효 Bearer 토큰이어도 401 대신 익명으로 통과시킨다. 그 외 라우트는 공통 규칙(내부/관리자/`anyRequest().authenticated()`)을 따른다. `SecurityConfig`가 공통 규칙 뒤에 적용하므로 admin/internal을 열 수 없다. `TradingSecurityPolicyTest`가 익명 GET 200·비GET·다른 경로 401을 잠근다
