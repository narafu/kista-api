## com.kista.tradingnotify (`:trading-core`)

com.kista.tradingnotify/ ← Spring Modulith 모듈(CLOSED, 2026-09-30 `trading.notify`에서 분리) — 매매 알림 6종과 그 게이트웨이. **순수 리스너·게이트웨이 sink(NamedInterface 없음, 외부 소비자 0)** — trading이 발행하는 이벤트 11종(`trading.application.event`, `"event"` NamedInterface)·privacy `PrivacyAlertRaisedEvent`를 구독하고 `trading.domain.model`("domain")/`trading.application.port.output`("port")를 읽을 뿐이라 trading은 이 모듈을 모른다(`trading → tradingnotify` 참조 0). 루트 notify 모듈이 아니라 trading-core 소속이며 이 프로세스(`kista-trading`)가 EPR 재발행 소유자다. `TradingApplication.scanBasePackages`에 명시 등록돼 있다(`TelegramProperties`는 `com.kista.platform.telegram` 소유라 `@ConfigurationPropertiesScan("com.kista.platform")`가 바인딩)
  application/port/output/ ← TradingNotifyPort/TradingRealtimeNotificationPort/TradingUserNotificationPort — `User` 대신 trading-core 소유 경량 프로필 타입(`trading.domain.model.TradingUserProfile`)을 받는 알림 출력 포트. 소비자는 모두 이 모듈 안이라(실측 grep: trading 핵심에서 주입하는 곳 0) 방향 역전 없이 그대로 두었다 — trading이 알림을 직접 호출하지 않고 이벤트만 발행하는 기존 패턴 덕분
  adapter/out/gateway/ ← TradingNotifyAdapter/TradingUserNotificationAdapter/RedisPushNotificationPublisher/RedisTradeEventPublisher/TradingUserProfiles + 매매 알림 리스너 6종(TradingAlertNotifier/CycleEndedNotifier/CycleLifecycleNotifier/OrderCancelFailureNotifier/TradingReportNotifier/PrivacyAlertNotifier). Telegram HTTP(`TelegramHttpClient`/`TelegramConfig`/`TelegramProperties`)는 root notify와 공용인 `com.kista.platform.telegram`을 주입받는다(구 package-private 사본 삭제, 빈 이름 `telegramRestClient`/`telegramHttpClient`). 실시간 알림 wire는 `contract.notify.TradeEventMessage`/`TradeEventEnvelope`(root 구독측과 공유)

**EPR 소유**: 이 프로세스(`kista-trading`)가 `trading.event_publication`(사본) EPR 재발행(`REPUBLISH_OUTSTANDING_EVENTS_ON_RESTART=true`, docker-compose.yml)의 소유자다 — 매매 알림 리스너가 여기 있어 재기동 시 자기 미완료 이벤트를 자기가 재발행한다. root `public.event_publication`은 `kista-scheduler`가 재발행한다(`kista-api`는 false 유지 — 둘 다 true면 이중 claim; scheduler는 `scanBasePackages`가 trading-core 패키지를 배제해 trading 리스너를 스캔하지 않는다).

**리스너 id 주의**: Modulith `event_publication.listener_id`는 리스너 FQCN+메서드로 저장된다 — 이 모듈로 패키지가 `com.kista.trading.notify.*` → `com.kista.tradingnotify.*`로 바뀌면서 기존 미완료 row가 고아가 된다. 배포 직전 확인·정리 절차는 `docs/agents/constraints.md` Flyway/EPR 절 참고.
