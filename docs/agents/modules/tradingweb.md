## com.kista.tradingweb (`:trading-core`)

com.kista.tradingweb/ ← Spring Modulith 앱셸 모듈. root `com.kista.web`과 대칭. `@ApplicationModule(Type.CLOSED)` — NamedInterface **0개**. 아무 모듈도 tradingweb을 참조하지 않는 sink라 순환에 참여할 수 없다(`HexagonalArchitectureTest.web_must_stay_pure_inbound_sink`가 `com.kista.web..`과 함께 `application.service`/`adapter.out` 의존 금지로 강제). trading-core 프로세스 전체(부팅·전역 web)에 걸치는 관심사만 두고, 특정 모듈 소유 코드는 소유 모듈로 보낼 것
  TradingApplication    ← `kista-trading` 프로세스 부팅 진입점(`@SpringBootApplication`+`@EntityScan`+`@ConfigurationPropertiesScan`+`@EnableScheduling`). `scanBasePackages`는 trading-core 소유 패키지 + 앱셸 `com.kista.tradingweb`만 나열해 root 패키지를 원천 배제한다. `bootJar` 매니페스트 `Start-Class`가 `com.kista.tradingweb.TradingApplication`(Dockerfile은 `java -jar trading-core.jar`라 변경 불필요). `@WebMvcTest`는 `@ContextConfiguration(classes = TradingApplication.class)`로 이 클래스를 지정한다(`com.kista.trading` 아래 테스트도 더는 패키지 상향 탐색으로 찾지 못한다)
  JpaRepositoryConfig   ← package-private `@Configuration` — `@EnableJpaRepositories`(trading/broker/account/privacy/marketcalendar). `TradingApplication`에 직접 붙이면 `@WebMvcTest` 슬라이스가 리포지토리 프록시 생성을 시도해 깨지므로 별도 클래스로 분리(슬라이스에서는 TypeExcludeFilter가 걸러낸다). `@DataJpaTest`는 `TradingCoreJpaTestConfig`(같은 스캔 범위)를 `@ContextConfiguration`으로 지정
  TradingExceptionHandler ← 프로세스 전역 `@RestControllerAdvice`(`basePackages` 없음, `@Order(HIGHEST_PRECEDENCE)`). trading-core 고유 예외 6종(`BrokerCredentialException` 422/`BrokerRateLimitException` 429/`ManualTradingException`·`OrderCancelException`·`PrivacyTradeConflictException`·`Account.DuplicateAccountException` 409) + `BrokerApiException` 503(title은 벤더 표기 도출, `AppErrorRaisedEvent` 발행 → `AppErrorStreamPublisher`가 `stream:app.error`로 root에 전달) + 범용 JDK/Spring 예외(`platform.web.ProblemDetailMappings.GENERIC`, `isClientDisconnect` 가드) + catch-all 500. root와 같은 JVM에 공존하지 않으므로 root `GlobalExceptionHandler`와 별개로 존재하되 매핑 테이블·탐색·검증 메시지는 `ProblemDetailMappings`를 공용한다
  라우트 정책 기여 없음 ← 이 프로세스의 모든 라우트가 인증 필수 또는 `/api/internal/**`이라 `platform.security.SecurityConfig`의 공통 규칙(내부/관리자/`anyRequest().authenticated()`)만으로 충분하다. `SecurityRoutePolicy` 빈이 없어도 `ObjectProvider`가 빈 스트림을 준다 — 빈 정책 클래스를 만들지 말 것
