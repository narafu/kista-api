## com.kista.notify (`:api`)

com.kista.notify/    ← Spring Modulith 모듈(CLOSED) — Telegram/FCM **순수 아웃바운드 알림 게이트웨이**(2026-09-30 결합도 재검토 5단계). 자체 UseCase 없음, 다른 모듈 유스케이스·trading-core HTTP 호출 0(`HexagonalArchitectureTest.notify_must_stay_pure_outbound_gateway`가 `..application.usecase..`·`org.springframework.web.client..` 의존을 잠금). `application.port.output`("port")·`domain.model`("domain") 공개, 나머지 internal. SSE wire 타입은 `com.kista.contract`(`TradeEventMessage`/`TradeEventEnvelope`)를 그대로 쓴다
  domain/model/       ← `NotificationRecipient(userId, nickname, notificationChannel, telegramBotToken, telegramChatId, rejectReason)` + `hasTelegramBot()` — notify가 알림 발송에 실제로 읽는 필드만 담은 notify 소유 투영(trading-core `TradingUserProfile`과 같은 접근). **`User` 애그리게이트를 모른다** — 변환은 호출자가 맡는다: user 이벤트 리스너 `CompositeUserNotificationAdapter`(이벤트가 ID만 담아 `UserPort`로 재조회한 `User`를 private static `toRecipient`로 변환)와 finance `FinanceRegistrationReminderNotifier`(자기 `User`를 생성자로 직접 매핑 — 7단계에서 이벤트화 예정). `NotificationChannel`은 `com.kista.sharedkernel` 소유(user 설정 저장 + notify 채널 라우팅 공유 어휘)
  application/port/output/ ← NotifyPort/UserNotificationPort(5메서드 모두 `NotificationRecipient`)/FcmDeviceTokenPort — "port". `contract.notify.TradeEventMessage`는 SSE 실시간 매매 알림 wire — trading-core `RedisTradeEventPublisher`(발행)와 root `RedisTradeEventSubscriber` → `TradeSseEmitterRegistry`(구독·kista-ui SSE)가 같은 타입(+ `TradeEventEnvelope`)을 컴파일 타임에 공유한다. `TradeLegSummary`(sharedkernel)와 별개 타입. `SseEmitterRegistry.notifyStatusChange`/`TradeSseEmitterRegistry.connect`·`send`는 포트 없이 구체 클래스로 직접 주입(호출자가 `adapter.in.web` 컨트롤러 2곳뿐이라 포트 역전 불필요)
  adapter/in/web/     ← FcmController/TradeStreamController(매매 이벤트 SSE)/StatusStreamController(`GET /api/auth/status-stream`) + dto/FcmTokenRequest
  adapter/out/gateway/ ← TelegramAdapter(관리자봇 `NotifyPort` — `notifyError`는 발송 전 `AppErrorRaisedEvent`를 발행해 admin 리스너가 `app_error_logs`에 저장하게 한다, trading-core `TradingNotifyAdapter.notifyError`와 동일 구조), CompositeUserNotificationAdapter(가입/승인/거절/재신청 리스너 4종 소유 → TelegramUserNotificationAdapter + FcmAdapter(사용자 알림)), TelegramBotInfoAdapter(user `TelegramBotInfoPort` 구현 — `TelegramHttpClient.getBotUsername` 위임), FcmConfig + 이벤트 리스너 5종(UserDeletedNotifier/AlertNotifier(구 MarketAlertNotifier+StatsAlertNotifier 병합)/SchedulerNotifier/UserFcmCleanupListener/PushNotificationRelayListener). **Telegram HTTP(`TelegramHttpClient`/`TelegramConfig`/`TelegramProperties`)는 `com.kista.platform.telegram`으로 통합**(trading-core `tradingnotify`와 공용) → `docs/agents/modules/platform.md`
  adapter/out/sse/    ← SseEmitterRegistry(사용자별)/TradeSseEmitterRegistry(매매 이벤트) — `sse` 경로 세그먼트 유지 필수(`HexagonalArchitectureTest.sse_emitter_registry_must_not_be_used_in_application_layer`의 `com.kista..adapter.out.sse..` 와일드카드)
  adapter/out/persistence/ ← FcmDeviceTokenEntity + FcmDeviceTokenJpaRepository + FcmDeviceTokenPersistenceAdapter

**남은 `notify → user` 의존(전부 허용 범위)**: user 이벤트 4종 구독(`NewUserRegisteredEvent`/`UserApprovedEvent`/`UserRejectedEvent`/`UserReappliedEvent`) + `UserPort`(`CompositeUserNotificationAdapter`·`PushNotificationRelayListener`의 사용자 조회, `User`는 그 두 클래스 안에서만 import) + `TelegramBotInfoPort` 구현. `notify → admin`은 0건이며 유지해야 한다(옛 `ErrorLogAspect`의 문자열 포인트컷 엣지는 삭제됐다 — `TelegramAdapter.notifyError`가 `AppErrorRaisedEvent`(sharedkernel)를 발행하고 admin `AppErrorRaisedListener`가 구독하는 이벤트 경로로 대체돼 양방향 모두 결합이 없다).

**텔레그램 봇 명령 채널(`/status`·`/history`·승인/거절 콜백)은 notify가 아니라 admin 소유** → `docs/agents/modules/admin.md` `adapter/in/telegram/`. **매매 알림 6종(TradingAlertNotifier/CycleEndedNotifier/CycleLifecycleNotifier/OrderCancelFailureNotifier/TradingReportNotifier/PrivacyAlertNotifier)은 이 모듈이 아니라 `com.kista.tradingnotify`(trading-core) 소유** → `docs/agents/modules/tradingnotify.md` 참고.
